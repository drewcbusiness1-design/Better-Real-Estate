# Better Real Estate v29.25 — Performance Root Cause + Notification Hierarchy + Stability

## Why this release exists
Live Chrome Network traces showed the same intermittent slowness across multiple pages was not a series of unrelated UI bugs. Shared backend/data work was taking seconds to tens of seconds, including a ~30s heartbeat that returned 504, a ~23s Network user request, and a ~6.7s wallet request. This release fixes the shared data path instead of patching pages one by one.

## Performance / Netlify cost
- Cold starts no longer run a sequential CREATE TABLE pass over every collection. Existing schema/indexes are discovered first and only missing objects are created.
- `loadDB()` reads the collection tables in one SQL round trip instead of one SELECT per collection.
- `saveDB()` now persists only changed/new/deleted rows instead of rewriting every row in every collection on each mutation.
- Ordinary authenticated requests no longer update `lastActiveAt`; the heartbeat owns activity writes.
- Browser heartbeat calls cannot overlap, stop in hidden tabs, and abort after 8 seconds rather than hanging indefinitely.
- Notification counts ride on the heartbeat response, avoiding a new polling loop.
- Profile listing + wallet data load concurrently.
- Any route that genuinely takes long enough to be perceptible receives a delayed theme-matched loading wheel; existing inline Network/Settings loading states now use the same wheel.

## Universal notification hierarchy
- Reuses the existing orange Messages-style badge language.
- Main Profile badge aggregates actionable/unread counts beneath Profile.
- Child destinations show their own counts beside the arrow without covering it.
- Current routed sources include Messages, Network friend requests, property/saved-search notifications, pending Affiliate applications for Admin, and open Admin Reports.
- Counts update from one summary endpoint and from heartbeat responses; no extra notification polling loop is introduced.

## Founding Member reconciliation
- Deleted Founder accounts no longer consume one of the live first-100 positions.
- Orphaned awards from accounts already deleted are automatically tombstoned.
- Surviving Founder ranks compact according to original qualifying signup order, so earlier deletions lower later users to the correct current rank.
- Returned positions are filled by the next eligible signup in chronological order.
- Deleted Founder identities keep an internal tombstone so the same identity cannot re-register and reclaim the benefit.
- Admin User Inspector now defaults newest signup first.

## Requested UX / Admin cleanup
- Removed the Shareable Profile Card feature/UI.
- `Start Preview` now actually enters the selected demo experience immediately after arming it.
- Affiliate Admin actions are state-correct: Pending = Approve / Deny; Approved = Suspend / Terminate; Suspended = Resume / Terminate.
- `Copy public profile` and the profile photo/edit sibling action use matching dimensions.
- Added breathing room below “or go Plus for unlimited” in the locked-listing panel.
- Existing working UI remains unchanged outside these targeted fixes.
