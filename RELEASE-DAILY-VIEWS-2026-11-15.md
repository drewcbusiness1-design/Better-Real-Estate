## Engineering and resource behavior

Browsing and Free AI use two dedicated, bounded, per-account records, initialized through the existing store. PostgreSQL admission uses conditional revision writes, including retries. Ordinary stale saves cannot overwrite those collections. Deleted-account cleanup removes quota records. No provider, dependency, environment variable, recurring job or integration was added.

Feed and search return bounded property previews without admission. Only an explicit full-detail request consumes the account allowance. There is no admission on scroll or feed polling. Account usage reads reuse the already loaded database snapshot; admission and free analysis reservations use targeted writes. AI uses the existing evidence, cache, failure cooldown, provider budgets and property-truth gates. Reservations prevent multiple simultaneous free jobs from spending beyond two available slots and prevent duplicate worker execution. A reservation abandoned before a terminal result expires after 30 minutes; an old token cannot settle a new reservation. Native requests with the existing `BetterRealEstate-iOS/` User-Agent and no browser fetch metadata retain the observed native API contract. This is compatibility routing, not a new native authentication mechanism.
