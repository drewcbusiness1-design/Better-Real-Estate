# Better Real Estate v29.15 — Production Deal Intelligence

This release replaces the repeated Deal Builder patch cycle with one evidence-first production workflow designed for correctness, provenance, bounded runtime, and low avoidable Netlify/API usage.

## Property identity
- A submitted full address now uses Regrid's ranked `/parcels/address` endpoint first. That endpoint already returns full parcel records and Regrid relevance scores, so Better avoids an unnecessary Typeahead + UUID round trip on normal lookups.
- Address matching normalizes street suffixes, cardinal directions (`West`/`W`, `North`/`N`, etc.), unit text, locality, state and ZIP before a parcel can become the subject. Common full-address pastes without commas are normalized too, so city/state text cannot poison street matching.
- Better requires an exact house/street guard plus either a strong local match or strong Regrid relevance score. Wrong-parcel matches remain release blockers.
- Regrid Typeahead is retained only as an optional Enterprise rescue path behind `REGRID_USE_TYPEAHEAD=true`. It is disabled by default so accounts without that product do not spend a failed request on every property.
- The workflow uses a new cache namespace so stale v29.14 evidence is not reused.

## Property truth
- Beds, baths, living area, year built, and property type retain field-level provenance.
- One high-quality source is retained as **Recorded** evidence, but the primary fact remains **Needs confirmation** until independently corroborated. The raw source value stays inspectable and cannot unlock a precise valuation by itself.
- Independent agreement promotes a field to verified only when at least one corroborating source is stronger than a syndicated portal. Multiple portal pages alone cannot turn a repeated upstream error into verified truth. Source conflicts remain visible and disputed values are withheld.
- A single-source property record alone cannot unlock a precise valuation.

## Public web corroboration
- Public-web research uses the existing OpenAI Responses API web-search tool only when deterministic evidence still needs corroboration or sold comps.
- The research model defaults to the cost-sensitive `gpt-5.6-luna` independently of the main synthesis model, uses no extra reasoning effort for structured evidence extraction, and can be overridden with `OPENAI_RESEARCH_MODEL` without requiring another key.
- When both subject-fact corroboration and sold-comp fallback are needed, Better performs one combined web-research call rather than two separate paid searches.
- Web-search requests explicitly request the consulted-source list. Better accepts a claim only when its URL was actually surfaced by web search and the property/address requirements pass.
- Zillow is never directly scraped or queried through an unauthorized API. A Zillow URL may be used only when legitimately surfaced through hosted public web search or later through separately approved/licensed access.

## Comps and ARV
- Configured authorized MLS closed sales remain first priority.
- Regrid nearby recorded sales are queried only after a subject parcel is identified.
- Public-web sold-comp discovery runs only when deterministic closed-sale evidence is insufficient.
- The comp engine rejects stale/distant/duplicate/low-similarity/outlier records, scores recency/distance/size/type/beds/baths/year, and applies a capped partial living-area adjustment instead of naive 1:1 $/sq-ft extrapolation. A precise ARV additionally requires independently established comp distance: normally at least 2 distance-verified nearby candidates among 3 usable closed sales, or 2 unusually strong recent/nearby distance-verified comps. Unknown-distance web comps may remain visible evidence but cannot unlock precise ARV.
- If those distance-verification and subject-identity gates are not met, ARV stays withheld rather than presenting unsupported precision.

## AI role
- AI is the final synthesis layer, never the source of record.
- It cannot invent comps, sale facts, source citations, or choose disputed property facts.
- Final synthesis is skipped when the property/comp gates fail.
- Final synthesis is cached by evidence fingerprint so reopening an unchanged property does not spend another AI call. If synthesis itself times out/fails, Better still returns the verified deterministic evidence/comp result, does not consume the user’s successful-analysis allowance, and stores a 30-minute synthesis-failure cooldown so repeated clicks do not immediately burn more AI calls.

## Netlify/API cost controls
- Property research is cached for 24 hours.
- Forced refresh is protected for 30 minutes.
- Concurrent identical research coalesces in-flight.
- The browser never resends its own evidence into final valuation; the server uses cached evidence.
- Normal Regrid identity is one ranked-address request rather than Typeahead + UUID.
- Public-web research is at most one search call for a property research pass when both facts and comps are missing.
- Reopening the same successfully analyzed property does not consume another Free/Plus new-property allowance and does not create duplicate successful-analysis analytics rows.

## Integrity and diagnostics
- Admin Research Diagnostics exposes cached identity, Regrid match candidates/scores, field evidence, MLS, nearby-sale, web, and comp-gate stages without triggering another provider call.
- Regression coverage includes the production failure address `503 W Grand Prairie St, Palestine, IL 62451`, cardinal-direction normalization, Regrid relevance scoring, conflict withholding, source-provenance rejection, comp gating, server-owned evidence, caching, and quota behavior.

## Live retrieval correction — 2026-09-29
- Kept the approved Regrid + authorized MLS + OpenAI web-search architecture; no new provider or dependency.
- Public-web corroboration now uses a bounded, location-aware, targeted search plan instead of a one-shot low-context lookup. It searches the exact address, major real-estate portals/broker pages, county/public-record terms, and sold/closed evidence as needed within the same research request.
- Web search now uses `medium` search context and low reasoning so the hosted search tool can perform a small agentic research sequence; request timeout remains bounded at 18 seconds.
- Single-source facts are now visibly shown as **Recorded** values in the evidence UI instead of hiding the value behind “Needs confirmation.” They remain excluded from verified subject facts and cannot unlock valuation until corroborated, preserving the Property Truth Gate.
- Research cache namespace is advanced to `v29.15-retrieval-r1` so previously cached empty/failed research cannot survive this correction.
- Tutorial/What’s New advances to version 44 with a focused property-research reliability step.
- Exact-address provenance checks, source URL validation, conflict withholding, comp gates, quota rules, cache controls, and server-owned evidence remain unchanged.
