# Better Real Estate v26.2 — Safe Production Patch

Built directly from the confirmed-good v26 source line. This patch intentionally changes only the requested areas.

## Fixed
- Deal Builder and Buyer CRM are registered in the authenticated renderer, so opening them no longer falls back to the public homepage and appears to sign the user out.

## Deal Builder membership allowance
- Free/trial: one successful property analysis total while the signup trial is active.
- Pro: five successful new-property analyses per UTC day.
- Platinum: unlimited.
- Wholesale Teams: unlimited.
- Admin: unlimited.
- Failed property-intelligence requests do not consume allowance.
- Reworking comps/calculator values on an already-returned analysis does not consume another allowance.
- The Deal Builder shows remaining allowance before analysis and refreshes it after a successful analysis.

## Leaderboard presentation
- Unified typography with the rest of Better Real Estate.
- Points are aligned to the far right of each member row.
- Added an explanatory panel for verified-closing points, monthly/all-time rankings, and Bronze/Silver/Gold thresholds.

## Scope protection
- Approved homepage is unchanged.
- No dependency or package-lock changes.
- No unrelated feature rewrites.

## Release QA correction
- Added the missing `.env.example` deployment template so the release is self-contained and the full integration suite can run from the packaged source.
- Added exhaustive release wiring regression coverage for every routed view, literal navigation target, authenticated Deal Builder/Buyer CRM endpoints, membership quota semantics, leaderboard scoring/alignment, and required environment documentation.
- Fixed a legacy-account leaderboard edge case: users created before a `points` value existed now safely receive 100 points instead of producing an invalid numeric value when an admin verifies a closing.
- The release test command now includes the v26.2-specific regression test and exhaustive release QA test.

## Route renderer hotfix QA
- Fixed a case-sensitive Buyer CRM renderer reference (`renderBuyerCrm` -> `renderBuyerCRM`) that caused `renderApp()` to throw before its error boundary, leaving authenticated routes as an empty shell (including Boost Picker).
- Strengthened release QA so every renderer referenced by the view map must resolve to a real function, case-sensitively.
- Re-audited every literal `go(...)` destination and every `ROUTED_VIEWS` entry against the renderer map.
