# Better Real Estate v29.16 — Multi-role identity

## Signup and profile roles
- Replaced the old Buyer/Seller-only signup choice with three clear role families: **Buyer / Investor**, **Seller / Wholesaler**, and **Lender / Funder**.
- Signup supports selecting **more than one role**. At least one is required.
- Roles do not gate platform features; they describe how a member participates and help the right people find each other.
- Existing members can update the same multi-role selection in **Settings → How you work**.

## Network and profile integration
- Network discovery now filters Buyers / Investors, Sellers / Wholesalers, and Lenders / Funders using the full multi-role set.
- Public profile, people cards, chats, requests, leaderboard/admin surfaces and signup alerts display the member's descriptive role labels rather than only the legacy primary role.
- Seller/wholesaler-specific buyer-list behavior works when Seller / Wholesaler is one of several selected roles.
- Buyer/seller email audience filters remain compatible with multi-role accounts.

## Compatibility and safety
- The server still maintains a legacy primary `role` value for existing features and old records, while the new `roles` array is the source for multi-role discovery/display.
- Existing accounts without a `roles` array are automatically treated as their current role and backfilled safely on login.
- `admin` remains impossible to select at signup and continues to be controlled only by the existing server-side admin allowlist.

## Onboarding
- What's New / guided tutorial version advanced to **50** with a role-discovery step explaining multi-role profiles, Network filters and Settings updates.

## Pre-deploy UI audit
- Multi-role cards intentionally reuse Better's existing form surfaces, borders, radii, typography, selected-state treatment, focus behavior and responsive breakpoints in both light and dark themes.
- Role cards collapse from three columns to one column below 620px so labels/descriptions remain readable on phones.
- Corrected the role-description color token to the existing `--ink-soft` design-system token and added a regression assertion so the signup component cannot depend on an undefined theme color.
